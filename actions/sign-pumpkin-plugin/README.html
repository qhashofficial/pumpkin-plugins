Sign Pumpkin plugin ​v0.0.4

Use this action after your workflow builds a plugin .wasm file. It adds Pumpkin's Ed25519 signature and release metadata to the file in place; it doesn't build the plugin. Run your publish or distribution step against the signed file.

See the action guide and API reference on the documentation site.

yaml
steps:
  - uses: filiphsps/pumpkin-plugins/actions/sign-pumpkin-plugin@sign-pumpkin-plugin-v0.0.4
    with:
      plugin-name: MyPlugin
      version: 1.2.3
      wasm-file: dist/my-plugin.wasm
      developer-name: My Name
      signing-key: ${{ secrets.PLUGIN_SIGNING_KEY }}

This example signs dist/my-plugin.wasm as MyPlugin version 1.2.3. The tag in uses is this action's Release Please version; it changes independently of the plugin version in version.

Before writing the file, the action replaces any existing signing sections and verifies the new signature. If a sibling <wasm-file>.sha256 checksum file exists, it updates that checksum to match the signed bytes. It uses the shared @pumpkin-plugins/signing implementation and the Node 24 runtime declared in action.yml, so you don't need a separate build or runner setup step.

For a release with several plugins, list each plugin's name, version, and .wasm path in a JSON manifest instead of setting the three single-file inputs:

json
[
  { "plugin-name": "MyPlugin", "version": "1.2.3", "wasm-file": "dist/my-plugin.wasm" }
]

Pass the manifest path through plugins-manifest. The developer name and signing key still apply to every entry:

yaml
steps:
  - uses: filiphsps/pumpkin-plugins/actions/sign-pumpkin-plugin@sign-pumpkin-plugin-v0.0.4
    with:
      plugins-manifest: dist/plugins.json
      developer-name: My Name
      signing-key: ${{ secrets.PLUGIN_SIGNING_KEY }}

The action prepares every signature before it writes any files, so a missing file or invalid manifest entry won't leave earlier plugins signed while later ones fail.

Inputs ​

InputRequiredDefaultDescription
plugin-nameNoSingle-file mode; exact plugin name embedded in the signature metadata
versionNoSingle-file mode; plugin version embedded without a leading v
wasm-fileNoSingle-file mode; path to the plugin .wasm file to sign
plugins-manifestNoBatch mode; JSON array of plugin-name, version, and wasm-file entries instead of single-file inputs
developer-nameYesDeveloper name embedded in signed metadata; required in either mode
signing-keyNo32-byte Ed25519 secret seed as 64 hexadecimal characters; required unless warn is true
warnNofalseWarn and leave the file unchanged when signing-key is empty instead of failing

Outputs ​

This action has no outputs.

Store the signing key in a protected GitHub secret. It must be a 32-byte Ed25519 seed written as 64 hexadecimal characters. If a workflow should continue without signing when the key is empty, set warn: true; the action warns and leaves each file unchanged. This option only skips an empty key: a malformed key, missing or invalid WebAssembly file, or failed signature verification still fails.
